# 麦肯锡方法论底座

这个文件不是行业事实库，而是本 skill 的分析操作系统。它回答的是“为什么这样拆题、这样验假设、这样组织结论”。

## 1. 七步法是主流程，不是装饰

默认按以下顺序工作：

1. 定义问题
2. 结构化拆解
3. 提出假设并排优先级
4. 制定研究计划
5. 展开分析
6. 综合洞察
7. 沟通建议

这个顺序的意义是：先把问题问对，再决定要找什么事实；先决定验证什么，再决定收什么数据。

## 2. MECE 用来防止分析混乱

MECE 指 `Mutually Exclusive, Collectively Exhaustive`，即相互独立、完全穷尽。

在这个 skill 里，MECE 主要用于：

- 拆分问题树
- 列假设清单
- 组织研究模块
- 组织高管汇报结构

实操要求：

- 同一层分支尽量不要重叠
- 先按一个维度拆，不要在同一层混用多个维度
- 如果做不到完全穷尽，也要明确剩余盲区

## 3. 假设驱动优先于数据打捞

零售问题天然指标很多。没有假设时，团队很容易在客流、转化、客单、毛利、库存、会员、竞对等一大堆数据里迷路。

因此先提出假设，再决定验证路径。

好假设通常满足：

- 能被验证或证伪
- 直接影响决策
- 指向一个关键驱动因子
- 不只是改写用户原话

示例：

- 弱假设：`华南市场表现不好。`
- 强假设：`华南市场同店增长停滞的首要驱动不是客流不足，而是高频刚需品缺货导致转化率下降。`

## 4. 80/20 原则用来排优先级

不是每个议题都值得同样深挖。优先顺序默认看两个维度：

- 对业务目标影响有多大
- 当前不确定性有多高

高影响、高不确定的议题优先验证。低影响或已知结论充分的议题，缩写处理即可。

## 5. 金字塔原理用于输出，而不是只用于 PPT

所有高管可读材料尽量遵守：

- 先给结论
- 再给支撑论据
- 最后给行动建议

每个层级都应能独立被阅读。管理者即使只看第一页，也能抓住核心判断和下一步动作。

## 6. 事实驱动不等于只认数字

事实可以来自不同来源，但必须分清来源与可信度：

- 用户提供的经营事实
- 企业内部数据
- 桌面研究
- 访谈与实地观察
- 仍待补充的空白

这意味着：

- 没有二手来源支持时，不要冒充“行业已知”
- 有定性洞察时，也要说明它来自谁、样本多大、局限是什么
- 当事实不足时，应输出“下一步怎么补证据”，而不是硬下结论

## 7. 零售问题的常见结构化入口

面对零售问题，优先考虑以下几个问题入口：

- 增长问题：客流、转化、客单、复购、品类结构
- 盈利问题：毛利、费用、坪效、人效、租售比、库存效率
- 市场进入问题：需求空间、竞争强度、渠道适配、自身能力
- 品类问题：角色定位、目标客群、价格带、陈列与动线、替代关系
- 竞争问题：直接竞对、替代渠道、线上渗透、即时零售分流

## 8. 什么时候要停下来承认“不知道”

如果缺少以下关键信息，应明确标注 `数据缺口` 或 `待验证项`：

- 时间范围
- 区域边界
- 目标客群
- 核心业务指标
- 竞对范围
- 决策目标

这不是分析失败，而是好分析的起点。
