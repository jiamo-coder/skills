# 产品数字化顾问能力官网规范

当用户要求建设、更新或评审“产品数字化顾问”的官网、能力地图或其他公开能力表达时读取本文件。官网是 Skill 的公开视图，不是客户项目档案，也不是没有证据的营销包装。

## 职责分工

- 产品数字化顾问定义受众、价值主张、能力边界、证据状态、内容结构和转化目标。
- 界面设计与实施调用当前环境可用的 `$small-type-ui-2026`，并在每次任务开始时按该 Skill 的动态清单核验最新版规范。
- UI Skill 只约束信息表达和体验质量，不得改变本 Skill 的业务方法、学习状态、权限或证据等级。
- 不能使用 UI 规范、案例来源或第三方网站的品牌、图片、公司信息、业务承诺或社会证明冒充本顾问资产。

## 公开事实来源

官网只从以下来源提取内容：

1. `SKILL.md` 中当前生效的工作原则、工作模式和交付边界。
2. `references/chain-enterprise-digital-ai.md` 中已核验的行业方法。
3. `references/prd-spec.md` 中可公开的交付规范。
4. `references/learning-ledger.md` 中已脱敏的全局方法及其状态。
5. 用户明确批准公开的其他材料。

项目级业务记忆、客户名称、自然人信息、简历、原始经营数据、商业秘密、凭据和未授权材料不得进入官网。不得把 `待验证经验` 写成已证明成果；可以作为“正在学习”展示，但必须保留状态和适用边界。

## 机器可读能力档案

官网以 `website/src/content/capability-profile.ts` 为公开内容入口。每条原则、能力、方向、证据和边界必须包含稳定 ID、来源引用、证据状态和适用边界。来源引用使用 `SKILL`、`CHAIN-METHOD`、`PRD-SPEC` 或真实存在的 `GL-XXX`。

`website/scripts/sync-skill-profile.mjs` 只执行确定性同步：

- 校验档案引用的 `GL-XXX` 在学习账本中存在。
- 统计学习条目总数及各状态数量。
- 更新公开档案的核验日期和生成统计文件。
- 检查公开链接和必需字段，不自行总结新的能力结论。

当重要教学或复盘改变了公开能力、思想、方向或边界时，在同一学习回合中人工判断是否需要最小更新能力档案，再运行同步校验。普通学习条目只自动更新统计，不自动变成官网主张。

## 官网信息与交互

- 默认单页连续叙事：价值、问题、思想、能力、方法、方向、证据、信任边界、公开使用入口。
- 每页只设一个主转化目标。当前默认主目标是查看能力地图；公开 GitHub Skill 是次级使用入口。
- 没有真实联系后台时不展示可提交表单，不伪造成功状态、客户 Logo、案例数据、评价、地址、备案或认证。
- 官网与企业工作台是不同平台，不使用后台侧栏、工作顶栏或卡片墙。
- 所有核心内容在无 JavaScript 时仍可阅读；移动菜单、焦点、锚点、错误恢复和减少动态效果必须可验收。

## 更新和发布边界

- 学习回合可以在路径明确时自动更新本地官网内容和生成统计，这是 Skill 包内部维护。
- GitHub 同步、Sites 发布、域名、公开访问和其他外部变更仍需用户对当前任务明确授权；长期学习授权不等于长期发布授权。
- 发布前运行 Skill 结构校验、内容来源校验、敏感信息检查、前端 Lint、生产构建和响应式验收。
- 生产地址确定前保持 `noindex`；启用索引前核对 canonical、robots、sitemap、Open Graph 和发布主体信息。
